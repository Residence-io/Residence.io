# Phase S1 local Supabase setup

Phase S1 establishes a reproducible, local-only Supabase foundation. It does not link a remote project and it does not replace NestJS, Prisma, the current session model, or private file storage.

## Prerequisites

- Node.js matching `.node-version`
- npm 11.9.0 or newer compatible npm 11 release
- Docker Desktop with Compose v2

Install with `npm ci`. The repository pins Supabase CLI `2.111.0`; do not install or depend on a floating global CLI.

## Commands

```text
npm run supabase:version
npm run supabase:start
npm run supabase:reset
npm run supabase:migrations
npm run supabase:types
npm run supabase:verify
npm run supabase:stop
```

`supabase:start` suppresses the local credentials generated by the CLI so they cannot leak into CI or shared terminal output. Retrieve them only when a later approved local workflow genuinely requires them, and never commit or paste them into logs. Phase S1 requires no remote Supabase URL, access token, project reference, or database password.

The application continues to use `DATABASE_URL` through NestJS and Prisma. Phase S1 adds no Supabase browser environment variables; those remain deferred to later phases.

## Local services

PostgreSQL 17 (the version supported by the pinned CLI), API gateway, Auth, Storage, Edge runtime, Studio, and local mail capture use the pinned `supabase/config.toml`. Realtime, Analytics, and database seeding are disabled. Auth signup is disabled. Only the empty `api` schema is exposed through the local Data API. Existing PostgreSQL 16 application regression tests remain in place to detect portability regressions.
